# Security and privacy

This package operates on synthetic inputs and mock previews only. Do not add credentials, real Account identifiers, deployment configuration, private datasets, runtime state, trading reports or original strategy parameters.

Report a suspected disclosure through the hosting provider's private security reporting feature when enabled. Avoid posting sensitive values in public issues. Before publication, the repository owner should enable private vulnerability reporting and review the chosen license and Git author metadata.

The publication scanner is a heuristic safeguard, not a guarantee. Review every diff, binary attachment, generated output and Git history before release. Git ignore rules do not remove files already tracked or historical objects.
